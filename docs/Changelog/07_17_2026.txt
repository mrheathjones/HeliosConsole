- Helios Console version: 1.0 Build: 44 (dev channel 1.0-d.44). ABM Lookup reliability, caching, and filtering rollout.
- Fixed ABM Lookup "Unable to Load ABM Inventory — The network connection was lost." Root cause was transport-layer, not credentials/config: URLSession reusing pooled connections that an SSL-inspecting proxy or Apple's edge had reset (NSURLError -1005), and enterprise SSL inspection breaking the app's opportunistic HTTP/3 (adding -1200 TLS teardowns). curl-based lookups were unaffected because they use one fresh TCP/HTTP2 connection per run.
- Added a transient-error retry to the ABM request path (ABMAPIService.abmRequest): GET-only (assign/unassign POSTs are never auto-resent), 4 attempts, retrying -1005/-1001/-1004/-1003/-1006/-1200 with 1→2→4→8s (cap 10) exponential backoff plus jitter to bridge a multi-second edge tarpit.
- Gave ABM/auth traffic its own URLSession (isolated connection pool, httpMaximumConnectionsPerHost=4, waitsForConnectivity) with HTTP/3 suppressed per request (URLRequest.assumesHTTP3Capable=false) so it stays on HTTP/2-over-TCP like the working curl path. Confirmed loading over corporate VPN + Zscaler SSL inspection.
- Added gentle pacing (250ms between per-server linkage sweeps) in buildAssignmentMap so a large org's burst of back-to-back large requests stays under the threshold that was triggering the edge to drop the reused connection mid-sweep.
- Graceful degradation on load: the org device list is primary content and now commits to the cache the instant the device page sweep finishes (unassigned), with the MDM server list + assignment map filling in as enrichment. If enrichment fails, the inventory is still shown (without assignment tags) instead of the whole load being discarded. At ~26k devices this is the bulk of the perceived load time removed.
- ABM inventory now preloads at the login screen (WelcomeLoginView), not after sign-in — ABM auth is app-level (ES256 client-credentials from the config profile) and independent of user login, so the sweep runs while the user authenticates.
- Added a persistent disk cache of the ABM inventory at ~/Library/Application Support/com.herojoneslabs.helios.console/abm-inventory-cache.json (devices, MDM servers, assignment map, fetch timestamp). Launch is cache-first: a valid snapshot is loaded and shown with no network fetch; a network sweep runs only on first run (no cache) or the Refresh button. Two guards keep a stale copy from ever being wrong: a schema version (bumped on model change) and a SHA-256 org fingerprint of clientId|baseURL (a snapshot from a different ABM tenant/credential set is discarded, not shown). The ABM Lookup header now shows date + time so a cache from an earlier launch is obviously old.
- Added a device-type filter to ABM Lookup (All / Mac / iPhone / iPad / Apple TV / Apple Watch / Apple Vision), matched on productFamily; the menu lists only the types actually present in the inventory.
- Added two ABM Lookup default-filter keys to the core appleBusinessManager config block (schemas/Helios_Core_SCHEMA.json): defaultMdmServerName (preselect the server filter by name, resolved to id case-insensitively; no match leaves "Any Server") and defaultDeviceType (all|mac|iphone|ipad|appletv|watch|vision, fail-safe to all). Both are operator-overridable starting points, not enforced locks.
- Fixed the default-filter application: the device-type default now applies independently of the server default. Previously a single flag deferred ALL defaults until the server list loaded whenever a server default was configured, so a slow or failed server-list load silently swallowed the device-type default too. Split into independent device-type (applies immediately) and server (applies when the server list resolves, retried on change) application, with NSLog diagnostics on the preload and default-application paths for field triage.
